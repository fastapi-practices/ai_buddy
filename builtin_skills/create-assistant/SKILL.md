# 创建助手

使用前先加载 `resource-tools` 能力获得所需工具；当前没有该能力时（如在 IM 通道或定时任务触发的对话中），告诉用户到网页端对话里操作，不要声称已完成

用户在新对话里选择助手后，助手的角色提示词会注入整个对话。适合“一类重复任务 + 固定做法”。用户只是一次性需求时，直接回答，不要建助手

## 流程

1. 弄清三件事：解决什么任务、给谁用、输出长什么样；用户已经说明的不要再问
2. 先在对话里给出草稿：名称、角色提示词、分类和 3 条开场白，请用户确认或提出修改
3. 按反馈修改草稿，直到用户认可后再创建；创建后的调整用 `update_assistant`，不要重复创建
4. 调用 `create_assistant`，用户会在创建前再确认一次参数
5. 创建后告诉用户：在新对话里选择该助手即可使用，想调整可以直接告诉我

## 修改已有助手

用户要调整已创建的助手时：先 `list_resources`（kind 为 `assistant`）取 ID，再调用 `update_assistant`，只传需要改的字段，未传的保持不变。`prompt` 要传完整的新内容，不是增量。内置助手不能修改，可以另建一个

## 字段

| 字段 | 要求 |
| --- | --- |
| `name` | 最多 64 个字符，点明用途，如“周报一键生成” |
| `prompt` | 角色提示词，写法见下 |
| `description` | 一句话说明，最多 512 个字符 |
| `category` | 见下表，选最贴近主要用途的一个 |
| `starters` | 开场白，建议 3 条，用用户的口吻，一句话，最多 8 条 |

分类：`efficiency` 效率办公、`writing` 写作创作、`translation` 翻译语言、`career` 职场求职、`development` 编程开发、`education` 学习教育、`lifestyle` 生活兴趣、`product` 产品运营、`legal` 法律合规、`finance` 金融财务

## 写角色提示词

按“角色、任务、约束、输出格式”四个要素组织，没有的要素不用硬凑：

- 第一句说清任务本身，不写“你是一位资深……专家”这类空头衔
- 写判断规则和取舍：遇到什么情况怎么处理，而不是堆形容词
- 明确输出格式和长度，默认给能直接使用的版本
- 写清不要做什么，如不编造数据、不说教、不写冗长铺垫
- 信息不足时的处理方式，如标“待补”或先问一个关键问题
- 控制在几百字内，越具体越好用

示例（日报速写）：

> 只保留今天做成的事、未完成原因、明天第一件事。短、具体、能扫完。不要写成散文，不要自我评价大段。

## 注意

- 同一用户下名称不能重复；工具提示名称已存在时，换个名字重试
- 工具返回创建失败时，按提示修正参数后再调用，不要告诉用户已创建
