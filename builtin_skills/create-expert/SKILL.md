# 创建专家

使用前先加载 `resource-tools` 能力获得所需工具；当前没有该能力时（如在 IM 通道或定时任务触发的对话中），告诉用户到网页端对话里操作，不要声称已完成

专家是可复用的模板：除了角色提示词，还能默认绑定 MCP、技能和知识库，并可一键填入成助手

## 专家还是助手

- 日常任务、固定输出风格：用 `create-assistant`
- 需要专业判断流程、要绑定知识库或工具的领域角色：用本技能

## 流程

1. 弄清领域、典型输入和期望的结论形式；用户已经说明的不要再问
2. 先在对话里给出草稿：名称、角色提示词和 3 条开场白，请用户确认或提出修改
3. 按反馈修改草稿，直到用户认可后再创建；创建后的调整用 `update_expert`，不要重复创建
4. 调用 `create_expert`，用户会在创建前再确认一次参数
5. 创建后告诉用户：可一键填入助手使用；还没绑定资源的，用户告诉你要绑定哪些再用 `update_expert` 补上

## 字段

| 字段 | 要求 |
| --- | --- |
| `name` | 最多 64 个字符，领域加角色，如“合同审阅” |
| `prompt` | 角色提示词，写法见下 |
| `description` | 一句话说明，最多 512 个字符 |
| `starters` | 开场白，建议 3 条，用用户的口吻，最多 8 条 |
| `mcp_ids`、`skill_ids`、`knowledge_ids` | 默认绑定的 MCP、技能和知识库，只绑定用户明确要求的 |

## 绑定资源

- 先用 `list_resources` 取 ID，kind 分别为 `mcp`、`skill`、`knowledge_base`，不要猜测 ID
- ID 不存在或不可用时工具会返回原因，据此修正，不要告诉用户已绑定
- 更新时这三个字段是整体替换，要保留原有绑定就一起传

## 修改已有专家

先 `list_resources`（kind 为 `expert`）取 ID，再调用 `update_expert`，只传需要改的字段，未传的保持不变。内置专家不能修改

## 写角色提示词

专家的提示词是一套判断框架，按顺序写：

1. 先看什么、缺什么信息就先问什么
2. 按哪几个维度评估，每个维度看什么
3. 结论怎么给：先结论后依据，风险按高中低分级
4. 不确定的地方明确标出，不编造依据、数据或引用
5. 什么情况下建议用户找真人专业人士

法律、医疗、金融等高风险领域，提示词里要写明：给出依据和不确定性，不冒充持证专业人士，不替用户做最终决定

## 注意

- 同一用户下名称不能重复；工具提示名称已存在时，换个名字重试
- 工具返回创建失败时，按提示修正参数后再调用，不要告诉用户已创建
